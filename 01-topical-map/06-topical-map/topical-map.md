## Cluster Representative (Centroid) Selection

A search engine does not evaluate every page in a cluster individually. It selects a **Cluster Representative (Centroid)** — the single page with the highest Information Density and Document Vocabulary breadth — and uses it to represent the entire query network. All other pages in the cluster derive their ranking authority from the Centroid.

### Centroid Selection Rule

The Centroid must be the page with the **most comprehensive vocabulary coverage** for the cluster. It must:

1. Contain entities no other page in the cluster mentions
2. Cover all the predicates assigned to the cluster
3. Have the deepest internal link structure (most incoming + outgoing links within the cluster)
4. Be the page most competitors have no equivalent for

### Centroid_Status Field

Each page in the topical map now carries a `Centroid_Status` field:

| Status | Meaning |
|---|---|
| `PRIMARY_CENTROID` | The main Centroid for a pillar-level cluster. Carries heaviest link weight. Must have highest vocabulary breadth. |
| `SUB_CENTROID` | Centroid for a sub-cluster within a pillar. Derives authority from PRIMARY_CENTROID. |
| `SATELLITE` | A spoke page that derives its ranking from a Centroid. Cannot outrank its Centroid. |
| `ENTITY_ANCHOR` | Special designation for the About page. Centroid for entity identity queries. |

### Centroid Damage Rule

If a Centroid page has a Tier 1 entailment gap (see `09-research/natural-language-inference-paths.md`), **all satellite pages in that cluster inherit the gap**. The engine evaluates the Centroid first, detects the deficiency, and applies the KBT cap to every page linked from it. Centroid quality is the single highest-leverage SEO factor on the domain.
