# Knowledge Graph Gap Analysis

Triggers: "compare knowledge graphs", "find gaps between notebooks", "what are clients asking that I don't write about", "content gap analysis", "semantic gap between knowledge bases".

## Theory

Compare a "Broadcast Knowledge" graph (what the agent publishes — blogs, marketing) against a "Demand Knowledge" graph (what clients actually ask — transcripts, support tickets). The goal: discover topics, relationships, and priorities present in the demand graph that are missing or underweighted in the broadcast graph.

### Hypotheses
- **H₀**: All clusters in KG_demand are subsumed by KG_broadcast
- **Hₐ**: Statistically significant sub-graphs exist in KG_demand with high semantic distance from KG_broadcast → these are content gaps

## Prerequisites

Both workspaces must exist in LightRAG with the **same embedding model** (e.g., `nomic-embed-text-v2-moe`). If embedding models differ, gap scores are meaningless.

Required files per workspace (generated by LightRAG ingestion):
- `kv_store_full_entities.json` — entity nodes with embedding vectors, frequency, degree
- `kv_store_full_relations.json` — relationship edges with source/target entity IDs
- `graph_chunk_entity_relation.graphml` — full graph structure (optional, for Jaccard)

## Three Gap Formulas

### 1. Semantic Distance (Micro Gap)

For every entity in KG_demand, find the closest entity in KG_broadcast via cosine similarity:

```
Gap_score(e_c) = 1 - max(CosineSim(v_c, v_a)) over all a in KG_broadcast
```

- Gap > 0.8: severe — agent has never written about this topic
- Gap 0.5–0.8: moderate — tangentially covered but semantically distant
- Gap < 0.5: covered — close match exists

### 2. Context Gap (Edge Differences)

When two topics appear together in client conversations but are disconnected in agent content:

```
Context_gap = 1 - |N(e_c) ∩ N(e_a)| / |N(e_c) ∪ N(e_a)|
```

Where N(e) is the set of neighboring entities (co-mentioned topics). High Jaccard distance means the agent covers both topics but never connects them — a relationship the client already understands.

### 3. Topic Priority Misalignment (Macro Gap)

Is the agent writing about the right things? Compare topic frequency distributions:

```
KL_divergence = Σ P_demand(e) · log(P_demand(e) / P_broadcast(e))
```

High KL divergence → agent is spending time on topics clients rarely ask about, while ignoring high-frequency concerns.

- Build frequency vectors from entity mention counts
- Normalize to probability distributions

## Pitfalls

- **Embedding model mismatch**: If workspaces use different models, gap scores are garbage. Verify both use `nomic-embed-text-v2-moe`.
- **Empty workspaces**: Client Knowledge must be ingested before gap analysis can run. If workspace doesn't exist, run `ingest_transcripts.py` first.
- **RAM pressure**: Loading both entity stores simultaneously can be heavy. Stream entities in batches if workspace is large (1000+ entities).
- **Entity format differences**: LightRAG entity JSON structure may vary by version. Always inspect the actual JSON keys before writing the loader.
- **Frequency normalization**: Raw entity mention counts need normalization by total corpus size. Don't compare absolute counts across corpora of different sizes.
